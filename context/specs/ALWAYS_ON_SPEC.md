## Build notes for 6.5's sign-in (2026-11-15, before building; the deploy itself is Ramin's)

Checked against the MCP authorization spec **2026-07-28** and Claude's connector docs (`claude.com/docs/connectors/building/authentication`): DCR is deprecated in the spec but still claude.ai's fallback; Client ID Metadata Documents (CIMD) are preferred; claude.ai's callback is `https://claude.ai/api/mcp/auth_callback` (Claude Code: a loopback port that changes per session).

- **Discovery:**
  - `/.well-known/oauth-protected-resource` and `/.well-known/oauth-protected-resource/mcp` serve `{ resource: <self>/mcp, authorization_servers: [<self>], scopes_supported, bearer_methods_supported: ["header"] }`.
  - The 401 from `/mcp` carries `resource_metadata` (the `/mcp` one) and `scope`.
  - `/.well-known/oauth-authorization-server` serves: the issuer; the authorize, token, register and revoke endpoints; `response_types ["code"]`; `grant_types ["authorization_code","refresh_token"]`; `code_challenge_methods ["S256"]`; `token_endpoint_auth_methods ["none"]`; `scopes_supported`; `client_id_metadata_document_supported: true`; `authorization_response_iss_parameter_supported: true`.
- **Clients:**
  - **CIMD:** a URL `client_id` is fetched (https only, no private addresses, 5 s, 64 KB, no redirects). It must be JSON with `client_id` equal to the URL, `client_name` and `redirect_uris`. It is cached by its Cache-Control (5 min to 24 h).
  - **DCR:** `POST /oauth/register` (JSON) for clients without CIMD.
- **Authorize:**
  - Checks: an exact redirect match (loopback addresses match on any port), PKCE S256 required, and `resource` equal to `<self>/mcp` when given.
  - Then the app's consent page `/oauth/consent` (he signs in first if he isn't). It shows the client's name, **the redirect's host**, and the scopes in Settings → Agents' words, with Allow (the one dark button) and Deny.
  - The redirect back carries `code`, `state` and `iss`.
- **Tokens:**
  - `POST /oauth/token` takes form-encoded bodies.
  - Codes are single use and last 10 minutes.
  - **Access tokens are our `rcl_` tokens** with the scopes he allowed, **valid for an hour**. A refresh renews the same row in place, so Settings → Agents shows one row per connection, named after the client.
  - **Refresh tokens rotate** and last 30 days. Using one twice revokes the connection. A dead one answers `invalid_grant`.
  - Revoking the row in Settings ends the connection.
- **The resource side:**
  - Only our own tokens are accepted.
  - An expired token gets a 401 with `WWW-Authenticate`.
  - Tokens are never read from the query string.
- **Tests:**
  - Integration: discovery, DCR, CIMD with a stubbed fetch, consent, PKCE, a reused code, refresh rotation and reuse, expiry, `/mcp` with the token.
  - A scripted run like claude.ai's against the running server (a loopback callback, the consent clicked in the browser at person speed); the consent page in light and dark, at 390 and desktop.
  - claude.ai itself needs his public HTTPS address (his deploy).
